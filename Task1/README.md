## 1. Карта IT-ландшафта

<img src="/img/Task1/it_landscape_map.drawio.svg" alt="IT Landscape Map" width="100%"/>

Матрица: строки — подразделения банка, столбцы — бизнес-возможности второго уровня из BCM.

### Бизнес-возможности

| Группа | Возможности |
|---|---|
| Продажи и маркетинг | Маркетинг, Продажи в отделениях, Продажи онлайн, Продажи через КЦ |
| Обслуживание продуктов | Депозитные продукты, Кредитные продукты, Платежи и счета |
| Операционная деятельность | Учёт операций, Оценка рисков, Коммуникации |

### Цветовое кодирование

| Цвет | Тип |
|---|---|
| Голубой | Собственная разработка (АБС, Сайт, Скоринговая система, SMS-шлюз) |
| Жёлтый | Платформа подрядчика (Интернет-банк, Система КЦ, Кредитный конвейер) |
| Красный | Внешняя система (Партнёрская система КЦ, БКИ, Телеком-оператор) |
| Зелёный | Ручной процесс (Email, Excel) |

### Ключевые выводы

1. **АБС** закрывает большинство бизнес-возможностей сети отделений и обоих бэк-офисов. Она одновременно является системой фронт-офиса, учётной системой и точкой интеграции — что создаёт высокую связанность.

2. **Email и Excel** как ячейки в колонке «Оценка рисков» — прямой индикатор отсутствия системной интеграции между отделом кредитования и бэк-офисом депозитов. Требование безопасности (изоляция ролей) компенсируется ручными процессами.

3. **IT-подразделение** владеет Интернет-банком и Сайтом, но ни один из этих каналов не присутствует в ячейках бизнес-подразделений — они не задействованы ни в одном продуктовом процессе. Это и есть целевой разрыв для цифровой трансформации.

4. **Партнёрский кол-центр** занимает ровно одну ячейку (Продажи через КЦ). Его система не интегрирована ни с одной внутренней системой банка.

5. **Команда цифровой трансформации** не присутствует ни в одной ячейке — она не является пользователем или владельцем действующих систем, а работает с целевым состоянием ландшафта.

## 2. Схема интеграции приложений

<img src="/img/Task1/integration_schema.drawio.svg" alt="Integration Schema" width="100%"/>

### Участники процессов

На схеме показаны шесть ключевых ролей (фиолетовые эллипсы):

- **Клиент** — взаимодействует с Интернет-банком и Сайтом напрямую (сейчас — только для платежей и просмотра информации)
- **Сотрудник отделения** — работает в АБС при приёме и оформлении заявок
- **Сотрудник бэк-офиса (депозиты)** — обрабатывает заявки в АБС, получает ставки через Email
- **Сотрудник бэк-офиса (кредиты)** — работает в АБС (раздел кредитного риска) и Excel; рассчитанные ставки передаёт по Email
- **Оператор КЦ** — заводит обращения в Системе кол-центра, они передаются в АБС
- **Оператор партнёрского КЦ** — работает в изолированной внешней системе без интеграции с банком

### Интеграции: процесс открытия депозита

| Источник | Приёмник | Способ | Описание |
|---|---|---|---|
| Система кол-центра | АБС | Интеграция | Передача обращений клиентов |
| АБС | SMS-шлюз | API | СМС-уведомление о готовой ставке |
| АБС (отдел кредитования) | Email | Вручную | Ставки кредитного риска, ежедневно |
| Email | Excel | Вручную | Данные для расчёта ставок депозита |
| Excel | АБС (фронт-офис) | Вручную | Рассчитанная ставка депозита |

### Интеграции: процесс открытия кредита

| Источник | Приёмник | Способ | Описание |
|---|---|---|---|
| АБС | Кредитный конвейер | Batch DB, 1×/сутки | Кредитные заявки и данные клиентов |
| АБС | Скоринговая система | Batch DB, 1×/сутки | История платежей клиента |
| Кредитный конвейер | Скоринговая система | API, онлайн | Данные заявки для скоринга |
| Скоринговая система | БКИ | API, онлайн | Запрос кредитной истории |
| Скоринговая система | Кредитный конвейер | API, онлайн | Оценка клиента (скоринговый балл) |
| Кредитный конвейер | АБС | Batch DB, 1×/сутки | Решения по одобренным кредитам |

### Ключевые выводы

1. **Депозитный процесс почти полностью ручной.** Цепочка АБС -> Email -> Excel -> Email -> АБС — четыре ручных шага там, где должна быть одна интеграция. Именно это делает мгновенное открытие депозита онлайн невозможным.

2. **Кредитный процесс более зрелый**, но батчевая синхронизация раз в сутки означает, что минимальное время принятия решения — двое суток (подача + возврат решения через АБС).

3. **Изоляция ролей в АБС** (менеджеры депозитов не видят кредитные данные и наоборот) не имеет системного решения и компенсируется Email-перепиской. Это нужно учитывать при проектировании нового решения: изоляция сохранится как требование безопасности.

4. **Интернет-банк** не подключён ни к депозитному, ни к кредитному процессу. Сайт не имеет ни одной интеграции с бэком. Оба канала — потенциальные точки входа для цифровых продуктов.

5. **Партнёрская система КЦ** — изолированный «чёрный ящик»: ни входящих, ни исходящих интеграций с банковскими системами.
