# Задание 2. FURPS+ таблица

[Описание задания](./TaskDescription.md)

Таблица содержит архитектурно-значимые требования к MVP цифровизации депозитного и кредитного направлений банка «Стандарт». Требования выделены на основе описания задания и IT-ландшафта.

Пометки:
- **Задание** — требование явно сформулировано в описании
- **Ландшафт** — вытекает из анализа текущего IT-ландшафта
- **Доп.** — дополнительное требование с обоснованием

| Код | Требования | Комментарий |
|---|---|---|
| F | **Функциональные (Functionality)** | |
| F1 | Публикация списка депозитов и кредитов с актуальными ставками на сайте и в интернет-банке | Задание. Для сайта — общие ставки; для интернет-банка — ещё и персонализированные |
| F2 | Персонализированные ставки по депозитам и предодобренные предложения по кредитам для авторизованных клиентов в интернет-банке | Задание. Требует предрасчёта и хранения индивидуальных условий по клиенту |
| F3 | Подача заявки на депозит с сайта новым клиентом (ФИО и номер телефона) | Задание. Клиент не идентифицирован; заявка передаётся в систему кол-центра |
| F4 | Подача заявки на депозит из интернет-банка (выбор счёта и суммы) с подтверждением СМС-кодом | Задание. Клиент идентифицирован |
| F5 | Подача заявки на кредит с сайта (ФИО и телефон; опционально — паспортные данные для получения предварительного решения) | Задание. При наличии паспорта запускается скоринг по данным БКИ и выдаётся решение |
| F6 | Подача заявки на кредит из интернет-банка (счёт зачисления, параметры заявки) с подтверждением СМС-кодом | Задание |
| F7 | Мгновенный предварительный скоринг нового клиента на сайте по данным бюро кредитных историй | Задание. Клиента нет в АБС — используются только внешние данные БКИ |
| F8 | Повторный упрощённый скоринг при подаче заявки на кредит по предодобренному предложению из интернет-банка | Задание. Предотвращает выдачу кредита по устаревшему решению |
| F9 | Единый справочник ставок по депозитам в АБС с доступом для сотрудников бэк-офиса депозитов и кредитов | Задание. Устранение Excel-файлов как единственного хранилища ставок |
| F10 | Процесс согласования ставок по депозитным заявкам реализован в АБС | Задание. Замена ручного согласования по email |
| F11 | Обработка заявки на депозит менеджером бэк-офиса в АБС: подтверждение условий и открытие счёта | Задание. MVP предполагает ручную обработку на стороне бэк-офиса |
| F12 | Передача заявок с сайта в систему кол-центра; возможность менеджера предложить клиенту особые условия | Задание |
| F13 | Сквозная обработка заявки: сотрудник отделения продолжает работу с той же заявкой, что подана онлайн | Задание. Исключает дублирование заявок при визите клиента в отделение |
| F14 | СМС-уведомления клиента при изменении статуса заявки: подтверждение ставки, открытие депозита, одобрение или отказ по кредиту, необходимость визита в офис | Задание |
| F15 | Обработка заявок по предодобренным кредитным предложениям в течение того же рабочего дня | Задание. Требует обхода пакетной интеграции АБС → Кредитный конвейер (раз в сутки) |
| F16 | Аудит и логирование операций подачи заявок и изменений их статусов | Доп. Необходимо для разбора клиентских претензий и расследования инцидентов |
| F17 | Идемпотентность операций подачи заявок | Доп. Двойной клик или сетевой ретрай не должны создавать дублирующие заявки |
| U | **Удобство использования (Usability)** | |
| U1 | Отклик UI по всем клиентским операциям в интернет-банке — в пределах миллисекунд | Задание |
| U2 | Соблюдение корпоративной дизайн-системы: цвета, шрифты, брендированные элементы интерфейса | Задание |
| U3 | Отображение актуального статуса заявки клиенту в интернет-банке | Доп. Клиент должен видеть, где находится заявка и что от него требуется; снижает нагрузку на кол-центр |
| U4 | Сквозной путь клиента «сайт / ИБ → отделение» без повторного ввода данных | Задание. При визите в отделение менеджер видит ту же заявку, что была подана онлайн |
| R | **Надёжность (Reliability)** | |
| R1 | Доступность клиентских сервисов (сайт, интернет-банк) — не ниже 99,9% (около 8,76 ч простоя в год) | Задание |
| R2 | Работа клиентских сервисов в режиме 24/7 | Задание |
| R3 | Развёртывание интернет-банка в двух ЦОД с автоматическим переключением при отказе основного | Задание. Сейчас работает один ЦОД, резервный переключается вручную |
| R4 | Независимость работоспособности интернет-банка от доступности АБС | Задание. Прямые вызовы АБС из ИБ недопустимы |
| R5 | Гарантированная доставка сообщений (заявок) между интернет-банком и бэкенд-системами при временных сбоях | Доп. Асинхронная интеграция через очереди не должна терять сообщения; решение — персистентность Kafka |
| R6 | Отсутствие единой точки отказа на критическом пути подачи заявки | Доп. Следствие требования 99,9%: каждый компонент критичного пути должен быть продублирован |
| P | **Производительность (Performance)** | |
| P1 | Загрузка справочных данных (ставки, списки продуктов, справочники) — не более ~200 мс | Задание. Сейчас некоторые справочники загружаются дольше секунды |
| P2 | Горизонтальное масштабирование новых сервисов интернет-банка | Задание |
| P3 | Равномерное распределение нагрузки между серверами, приложениями и ЦОД | Задание |
| P4 | Исключение прямых синхронных вызовов API АБС из интернет-банка | Задание / ландшафт. БД АБС перегружена; прямая интеграция создаёт риск деградации всего банка |
| P5 | Система кредитного скоринга не должна получать дополнительную нагрузку от предрасчётов | Задание. Скоринг уже нагружен в рабочие часы |
| P6 | Кеширование справочников ставок и продуктов на стороне интернет-банка и сайта | Доп. Единственный реалистичный способ обеспечить отклик в миллисекунды без обращения к АБС на каждый запрос |
| P7 | Онлайн-канал передачи заявок по предодобренным кредитам напрямую в Кредитный конвейер (в обход пакетного обмена с АБС) | Доп. Пакетный обмен раз в сутки несовместим с требованием «обработка в тот же день» |
| S | **Поддерживаемость (Supportability)** | |
| S1 | Максимальное использование существующих технологий банка: MS SQL, Oracle, Java, Python, .NET | Задание |
| S2 | Новые технологии должны быть совместимы с существующими платформами разработки | Задание |
| S3 | По любым вводимым технологиям в банке должна быть внутренняя экспертиза (хотя бы на уровне языков программирования) | Задание |
| S4 | Apache Kafka — стандарт для очередей сообщений во всех новых интеграциях | Задание |
| S5 | Перевод интернет-банка на микросервисную архитектуру в рамках задачи открытия депозитов (без полного рефакторинга монолита) | Задание. Ограниченный переход: только сервисы нового процесса |
| S6 | СМС-функционал для подтверждения и уведомлений реализуется командой банка без доработки ядра ИБ подрядчиком | Задание. Доработка ядра дорогая и вне прямого контроля банка |
| S7 | Разработка технической документации для дальнейшего расширения системы | Задание |
| S8 | CI/CD-пайплайны для новых микросервисов интернет-банка | Доп. Без автоматизации поставок скорость разработки при переходе на микросервисы существенно снижается |
| S9 | Централизованный мониторинг, алертинг и сбор логов для новых сервисов | Доп. Без наблюдаемости невозможно выполнить SLA 99,9% и быстро локализовать инциденты |
| +R | **Ограничения (Restrictions)** | |
| +R1 | Новые клиенты обязаны пройти идентификацию в отделении с предъявлением документов | Задание. Требование законодательства — банк не может принять нового клиента полностью онлайн |
| +R2 | Разделение доступа к данным: сотрудники бэк-офиса депозитов и бэк-офиса кредитов не имеют доступа к данным друг друга | Задание |
| +R3 | Шифрование трафика между клиентом и сайтом (TLS) | Задание. На сайте передаются чувствительные персональные данные |
| +R4 | Шифрование трафика между клиентом и интернет-банком (TLS) | Задание |
| +R5 | АБС поддерживает только вертикальное масштабирование из-за монолитной архитектуры на Oracle с PL/SQL-логикой | Ландшафт. Технический потолок: высоконагруженные сценарии не должны упираться в АБС |
| +R6 | БД АБС перегружена — прямая онлайн-интеграция интернет-банка с АБС недопустима | Задание / ландшафт |
| +R7 | Текущая версия платформы интернет-банка (ASP.NET MVC 4.5 / .NET Framework) несовместима с Apache Kafka | Задание. Новые сервисы, использующие Kafka, необходимо выносить за пределы монолита |
| +R8 | Обмен данными между АБС и Кредитным конвейером — пакетный, раз в сутки; ускорить невозможно | Задание. Для онлайн-подачи кредита из интернет-банка нужен отдельный канал |
| +R9 | Ставки по депозитам сейчас хранятся исключительно в Excel-файлах | Задание. Цифровизация невозможна без переноса справочника ставок в АБС |
| +R10 | Кредитный конвейер и система кредитного скоринга поддерживают горизонтальное масштабирование и работу 24/7 | Задание. Эти системы могут использоваться как источник онлайн-данных для новых сервисов |
